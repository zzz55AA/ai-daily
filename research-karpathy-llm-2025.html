速读

十分钟就能带走的主线

  1. 你在和什么说话？先不是“魔法智能体”，而是一条被训练成会续写 token 的流水线。聊天框后面，是预训练、监督微调、强化学习三步。0:00:00 ↗ 0:59:23 ↗
  2. 文字如何变成计算？文本要切成有限符号表里的 token。这些符号是唯一 ID，不是可加减的数。序列长度很珍贵，所以用字节对编码（BPE）换更短的序列。GPT-4 词表，讲座给出 100,277。0:07:50 ↗ 0:11:48 ↗
  3. 模型到底在学什么？在一段上下文里预测下一个 token。训练是把正确那个 token 的概率往上推；参数是一排可拧的旋钮。预训练完成后，得到的是“互联网文档模拟器”，不是助手。0:16:49 ↗ 0:21:37 ↗ 0:48:09 ↗
  4. 训练和推理不是一回事。训练改参数；你使用产品时，参数通常已经固定，只在推理：按概率采样，接到后面，再采下一个。所以同一句话多问一次，答案可以不一样。0:26:11 ↗ 0:30:29 ↗
  5. 助手是后来装上去的。监督微调扔掉互联网文档集，改用对话示范继续训练。你面对的大致是：对“人类标注员会怎样按公司说明书回答”的即时模拟，而不是一个有自我的人。1:03:09 ↗ 1:17:21 ↗
  6. 参数不是工作记忆。写在权重里的是模糊回忆；写在上下文里的才是当前工作记忆。幻觉常常是因为训练里“谁是某某”都被自信地答完了，模型就学了这种腔，而不是先承认不知道。工具把检索结果贴进上下文，就是在补工作记忆。1:22:17 ↗ 1:39:23 ↗
  7. 模型需要 token 来思考。每个新 token 只能做有限计算。逼它立刻给答案，等于要求一步跳完；把步骤写出来，是把计算摊开。这些步骤首先是写给模型自己的。1:49:20 ↗ 1:53:39 ↗
  8. 能力像瑞士奶酪。整体可以很强，却会在拼写、计数、9.11 和 9.9 这类地方突然出现空洞。强化学习能在可验证领域里长出回看、重算等策略；RLHF 能改善文风，但奖励模型可被钻空子，不能无限优化。2:04:53 ↗ 3:06:13 ↗ 3:26:13 ↗
  9. 怎么用？当工具箱里的工具：要初稿、要启发、要提问，但检查工作，并对产物负责。3:30:32 ↗
01

你到底在和什么说话

讲座原意开场要解决的不是公式，而是心理模型：这个文本框后面是什么，该往里放什么，返回来的词又是怎么来的。他承认它在某些方面出色，同时强调它擅长的和糟糕的都不均衡，还有不少锋利的边。0:00:00 ↗

他选择按整条建造流水线往下讲，并尽量保持一般听众能跟上。后面几乎所有“怪异表现”，都可以在这条流水线上找到来源：数据如何过滤、符号如何切分、训练时模仿了什么、推理时又只能做多大的一步计算。

机制先有会续写互联网文本的基座模型，再有对话数据和强化学习，把它变成助手。三步不是三个不同的魔法，多半是同一类训练，换了数据与目标。
例子你在 ChatGPT 里打字，看到的几乎都是推理：参数早已训练好并被固定。0:30:29 ↗
误区不要一上来就把它当成一个有连续自我的人，也不要因为它会说话，就认为它在查资料。默认情况下，它只是在往后续写统计上像那么回事的 token。
02

从“下载互联网”到过滤后的文本

讲座原意预训练的第一步，是下载并处理公开文本。他用来建立直觉的公开样本是 Hugging Face 的 FineWeb：目标是量大、质量高、来源多样，因为多样性会进入模型所能表现的知识面。主要提供方内部都会有某种等价物。0:01:06 ↗

一个反直觉的数字是：经过大幅过滤后，FineWeb 大约只占 44TB 磁盘。互联网很大，但这里用的是文本，而且过滤很凶，所以“并不算天文数字”，差不多能放进一块硬盘。0:02:15 ↗ 起点通常是 Common Crawl（他提到该组织自 2007 年爬网，并举 2024 年约 27 亿页面为例）。随后是一长串处理：URL 黑名单去掉恶意、垃圾、成人等站点；从 HTML 里抽出正文、去掉导航和样式；语言识别（FineWeb 举例只保留英语占比超过 65% 的页面，这是产品选择，会直接影响多语言能力）；去重；以及尽量去掉地址、社保号一类个人可识别信息。0:02:48 ↗

他把前 200 个页面拼在一起给你看：那是一大块“互联网纹理”。接下来的任务，就是让神经网络学会模拟这种纹理如何流动。0:07:02 ↗

2026 补充我们核到的 FineWeb 官方介绍仍把该数据集写成“最初约 15 万亿 token”。讲座后数据集卡片已写“超过 18.5 万亿（最初 15 万亿）”。44TB 是讲座对当时博文的转述，本篇没有在当前卡片上核到同一磁盘数字。不要把 18.5 万亿写回 2025 年 2 月的口播。
机制进入模型的不是“整个互联网”，而是被过滤过的文本统计。过滤规则会变成模型的性格和盲区。
例子若几乎丢掉西班牙语，后来的模型就不太会西语。FineWeb 偏英语，是明确的设计选择。0:05:06 ↗
误区看到“训练数据来自互联网”，不要以为模型在推理时还能上网；那是训练前的离线语料，而且已经损失了大量页面。
03

Token：模型真正在读的字母表

讲座原意神经网络要的是有限符号表上的一维序列。屏幕上看起来像两维排版，对模型来说只是从左到右、从上到下的一条线。0:07:50 ↗

若用 UTF-8 看成原始比特，符号只有 0 和 1，序列会极长；而序列长度在这些网络里是稀缺资源。把 8 个比特收成一个字节，符号变成 256 种，长度缩短 8 倍。他特别叮嘱：请把这些数字想成唯一 ID 或唯一符号，最好想象成不同的标记，而不是可以拿来做算术的数。0:10:19 ↗

生产模型还会继续压缩。方法是字节对编码（BPE）：反复找到最常见的相邻符号，合并成新符号。词表变大，序列变短。他给出一个实践上相当好的规模：大约 10 万种符号；具体到 GPT-4，是 100,277。这个“从原文到符号、再从符号回到原文”的过程就叫 tokenization。0:11:02 ↗

演示里他用公开的分词查看工具看 GPT-4 的 CL100KBase： “hello world” 是两个 token（“hello” 编号 15339，以及带空格的 “ world” 编号 1917）。大小写、空格一变，切分就变。他预告后面还会回到切分，因为它能解释拼写和计数上的笨拙。0:12:20 ↗

机制模型从不逐字母阅读。它看见的是切好的块。块的边界由压缩效率决定，不必符合人类的单词直觉。
例子“hello world”、改大写、插入两个空格，会得到不同的 ID 序列。0:12:43 ↗
误区不要以为模型“看见了单词里的每个字母”。后面草莓单词里有几个 r、以及某些比较大小的事故，都和这一点有关。
04

预测下一个词：输入、输出和一次示意性更新

讲座原意FineWeb 不仅是约 44TB，讲座转述它还是大约 15 万亿 token 的序列。把文本换成 ID 之后，训练要做的事很单纯：建模这些 token 如何一个接一个出现。0:14:40 ↗

做法是从数据里随机切一段窗口当上下文，长度从 0 到某个上限（他举例 8,000，也说 4,000 或 16,000 都常见；再长会非常贵）。网络输出词表里每个 token 的概率。网络一开始是随机的，所以这些概率一开始也接近乱猜。因为窗口来自真实数据，我们其实知道下一个真值。于是有一套数学手续，把正确那个 token 的概率略微推高，把其余的略微压低。对整份数据、在大批窗口上同时这样做，就是训练。0:15:38 ↗

示意（来自讲座自己的玩具数字，不是某次真实训练日志）： 上下文 4 个 token → 网络给真值 token「post」（ID 3962）约 3% 更新后，同一上下文再次输入 → 该概率或许变成约 4%，其它 token 相应下降 这只是为了说明“拧旋钮”的方向，不能当成可复现实验。
机制训练从不要求模型“理解世界”作为显式目标。它只要求：在统计上，把真实语料里的下一词猜得更准。
例子上面 3% 变 4% 的步进，是他画在屏幕上的教学例子。0:17:42 ↗
误区不要把“概率变高”理解成“它现在确信这是事实”。变高的是“在训练分布里，这个续写更像真实文本”。流畅和正确不是一回事。
05

网络内部：旋钮、Transformer，以及原片没展开的地方

讲座原意输入 token 会和网络的参数 / 权重一起进入一个巨大的数学表达式。现代网络有数十亿甚至更多参数；一开始它们是随机的，预测也是随机的。训练就是反复更新这些参数，使输出与训练集里的统计模式一致。他把参数比作 DJ 台上的旋钮：拧不同的组合，就会对任意输入序列给出不同的下一词预测。0:20:13 ↗

他用一个极简式子说明：里面不过是乘、加、指数、除法这类运算。研究架构，是在找既有表达力、又容易优化、还便于并行的表达式，而不是在堆“吓人的数学”。接着他打开一个可视化网站，展示一个约 85,000 参数、名叫 Transformer 的网络：token 先被嵌入成向量，再流过层归一化、矩阵乘法、softmax，以及注意力块和多层感知机块。中间数值可以松散地想成“合成神经元的发放率”，但他立刻警告：不要太按生物神经元去想——这些单元非常简单，整份表达式从输入到输出是无状态、没有记忆的固定映射。0:23:09 ↗

然后他明确收住：不打算深讲这些变换的数学细节，也“并不认为那有多重要”。真正要抓住的是——这是一个由固定参数集参数化的数学函数，拧参数会改变预测，训练就是找到一组与数据相符的参数。0:25:24 ↗

教学解释原片点到了嵌入、注意力块和 MLP，但没有推导注意力公式。若只需一个工作直觉：注意力让每个位置可以查看上下文里的其它位置并加权混合信息；MLP 再在每个位置上做非线性变换。堆叠多层后，模型能在上下文里做更复杂的组合。这是为了补上下文而写的教学说明，不是讲座推导。
机制知识并不以“一条条数据库记录”的形式存放。它分布在参数里，只有通过续写才会被调出来。
例子可视化里那个约 8.5 万参数的小 Transformer，只是为了让你看见信息如何从输入流到下一词概率。0:23:19 ↗
误区不要因为出现了“注意力”“神经元”这些词，就以为已经理解了实现细节；也不要把无状态的前向计算，想成一个能在权重里“当场记事”的大脑。
06

推理：掷一枚有偏的硬币

讲座原意训练之外，还有一个同样重要的阶段：推理，也就是从模型生成新数据。给一个前缀，网络吐出下一词的概率分布；你按这个分布采样——他比喻成掷一枚有偏硬币——得到一个具体 token，接到后面，再问下一个。0:26:03 ↗

采样是随机的。有时会碰巧复现训练集里的一小段，有时会走到训练集里从未原样出现过的 token，于是很快生成“风格相近、但并非逐字复制”的文本。他称之为对训练数据的 remix，统计性质相似，但并不等同。0:28:14 ↗

流程上，下载互联网并分词通常只做一次；然后你会训练许多不同设置的网络；一旦得到一组满意的参数，就冻结它们，专门做推理。你和 ChatGPT 对话时，模型可能几个月前就已经训练完毕，不再发生训练，只是在补全 token。0:29:51 ↗

为把这件事做实，他展示了自己用 llm.c 复现 GPT-2 的训练现场。GPT-2（2019）被他称作“第一次拼出可辨认的现代技术栈”：Transformer，约 16 亿参数（稍后讲到正式发布时，他改口并强调发布的是约 15 亿 参数的基座模型），最大上下文 1,024，大约在 1,000 亿 token 上训练。以今天标准，这些都偏小：现代上下文可到几十万甚至号称百万，FineWeb 这类数据已是 15 万亿量级。0:31:10 ↗

他引用的成本对照是：2019 年训练 GPT-2 估计约 4 万美元；他这次复现大约一天、约 600 美元，而且“还没怎么拼命”，觉得当时已经有望降到约 100 美元。原因主要是数据过滤更精，以及硬件和软件都快了很多。现场每一行是一次更新，每次在约 100 万个 token 上同时改进预测，大约 7 秒一步，计划 32,000 步，合计约 330 亿 token。研究人员盯着的是 loss：越低越好，对应下一词预测更准。每隔 20 步他会做一次推理，看模型胡乱续写得像不像话。0:33:30 ↗ 0:35:18 ↗

讲座原意这组 600 美元、100 万 token / 7 秒、32,000 步的数字，描述的是他自己的复现实验，不是 OpenAI 当年训练 GPT-2 的原始日志。
机制训练在改旋钮；推理在旋钮固定后采样。随机采样解释了“同一提示，多次回答可以分叉”。
例子他在讲解里把序列采到一个并非原数据里的 “article”，以说明生成是 remix，不是复读机。0:27:54 ↗
误区讲座几乎没有单独讲温度（temperature）这类采样旋钮。教学解释产品里常见的温度，只是在更“尖”或更“平”的分布之间选择，不宜当成讲座原话。
07

基座模型：昂贵的自动补全，有损的互联网压缩

讲座原意预训练结束得到的是基座模型：互联网文本的 token 模拟器。它还不是助手。问“二加二等于几”，它不会规规矩矩回答“四，还需要什么帮助”，而会把这串字当成前缀，按网页语料的统计往下续。他称之为“非常昂贵的自动补全”。同一前缀每次采样都会走向不同领地，因为它是随机系统，而且每次几乎从零开始。0:43:23 ↗ 0:47:48 ↗

尽管如此，为了把下一词预测好，模型已经在参数里储存了大量关于世界的统计知识。他把 Llama 3.1 的 4,050 亿 参数（在约 15 万亿 token 上训练，由 Meta 发布）比作互联网的压缩包：不是无损压缩，而是有损的，留下的是一种 gestalt（总体印象）。常见的内容更容易被“记对”，罕见的内容更不可信，因为信息并不是显式存储的条目，只是模糊的回忆。0:50:10 ↗

要引出这些知识，需要把提示写成“像文档的开头”。例如用“巴黎十大必看地标如下”去引诱它续写清单。结果可能大致对，但不能当百科全书。他进一步演示：把维基百科《斑马》条目的第一句贴进去，基座模型可以接着把条目写得很像；但若问它训练截止之后的选举，它会生成不同的平行宇宙，而且每次采样都不一样——因为它没有实时记忆，只会按“选举报道通常长什么样”去编。0:50:34 ↗ 0:52:08 ↗

哪怕只有基座模型，也可以用上下文里的示范让它扮演助手：先写几轮“人类 / 助手”对话，再提出真正的问题。他甚至让 ChatGPT 帮忙写这样的前缀，然后问“为什么天是蓝的”，模型会按助手口吻谈到瑞利散射。若去掉这些示范、只丢一句问题，基座模型又会乱跑。这已经是在用上下文做工作记忆，但还很脆弱，助手人格并不稳定。0:57:31 ↗

讲座原意发布一个基座模型，通常需要两样东西：描述网络如何连接的代码（往往只有几百行），以及那一长串已经调好的参数。价值主要在后者。基座模型很少被单独发布，因为它只是走向助手的第一步。0:44:16 ↗

机制预训练把互联网压进参数；基座模型会“做梦般”生成网页，而不是回答问题。上下文里的示范可以暂时借来助手外形，但那不是后训练装上的稳定人格。
例子在 Hyperbolic 上必须明确选择 Llama 3.1 405B 的 base 而不是 instruct，才能看到这种“不是助手”的行为。0:47:03 ↗
误区不要把基座模型偶尔答对“二加二”当成它已经是产品助手；也不要把有损压缩里的模糊回忆，当成可引用的事实库。
08

监督微调：如何把助手装上去

讲座原意要的不是再生成网页，而是多轮对话里的助手：会回答“二加二”，也会在不该帮忙时拒绝。神经网络无法用传统 if-else 直接编程这种行为，只能通过数据来隐式编程。于是把预训练用的互联网文档集丢掉，换上一份人类与助手的对话集，继续训练。模型会很快转向新的统计，在推理时模仿标注员在同类情境下会写的回复。1:01:07 ↗

算力对比很悬殊：预训练在实践中可能大约三个月、数千台机器；后训练往往短得多，他举例大约三小时，因为对话集比互联网小很多。1:04:11 ↗

数据从哪里来？经典公开说明来自 InstructGPT：公司雇用承包商（讲座提到 Upwork、Scale AI）按标注说明书撰写提示和“理想助手回复”。说明书要求有帮助、诚实、无害，真实文档可以长达数百页。公开可参考的复现数据集他提到 OpenAssistant。现代数据则大量借助模型起草、再经人编辑，UltraChat 是其中一个例子，话题非常多样。多样性让人格能泛化到从未见过的提示。1:10:41 ↗

这引出全片最“泄气”也最清醒的一句：你并不是在和一个魔法 AI 说话，而大致是在和一个平均标注员的即时模拟说话。这个人往往受过相当训练，代码问题甚至可能来自专家标注；但如果某个问题就在微调集里，你看到的回答很可能接近当时那份“标准答案”。1:17:21 ↗

第三方解读Understanding Machine 的导读把这一段称为整场讲座的情感中心：助手人格来自受雇写作者和公司说明书，而不是一个内在自我。本篇同意这个读法，但仍以口播为准。
机制同一套下一词训练，换了对话数据，模型就学会“助手该怎么说话”，包括拒绝。
例子标注说明书里对“有帮助 / 诚实 / 无害”的优先级，会直接变成产品后来的拒答风格。1:10:41 ↗
误区不要把流畅、有礼貌、会拒绝，自动理解成“它真的理解并认同这些原则”。它首先是在模仿示范的统计形状。
09

幻觉、工具，以及两种完全不同的记忆

讲座原意他从这里进入所谓的模型“心理学”：训练流水线带来的涌现认知效应。第一件是幻觉——模型一本正经地编造。早期助手这个问题很严重，后来有所缓解，但他先要解释它为什么几乎不可避免。1:20:34 ↗

设想微调集里全是“某某人是谁”的问答：汤姆·克鲁斯、某位参议员、成吉思汗。标注员要么本来知道，要么会去查，然后写出自信、完整的答案。到了测试时，你拿一个他随口编的名字 Orson Kovats 去问。即便网络内部某处“感觉这个名字不熟”，它也往往不会说“我不知道”——因为训练里这类问题都是被自信答完的。它会接过那种腔，给出统计上最像那么回事的猜测。这些系统默认并不联网，他称之为 statistical token tumblers：只是在采样下一个 token。1:21:17 ↗

演示里，较老的 Falcon 7B Instruct 把这个不存在的人说成美国科幻作家、1950 年代剧中角色、前小联盟球员，每次都不一样。更新的 ChatGPT 在他禁止使用工具时，可以承认自己并不认识这个人；若允许搜索，则会先发出搜索，再根据塞进上下文的网页来引用。1:23:19 ↗

如何缓解？一条路是教会模型“在自己确实不知道时说不知道”。他举 Meta 在 Llama 3 系列上的做法：用文档生成问答，多次询问模型，再用模型评判对错；若经常答错，就把“我不知道”写进训练。另一条路是工具：模型发出特殊 token，推理程序暂停，去执行搜索，把网页文本塞回上下文，模型再基于这些可见材料作答并引用。只需相对少量的示范对话，模型就能学会在不该仅靠回忆时去检索。1:25:22 ↗ 1:34:47 ↗

由此得到全片最重要的对比之一：参数里的知识是模糊回忆；上下文窗口里的知识是工作记忆。 这很像人：很久以前读过的书对不上原文，刚摊在桌上的材料却可以准确引用。实践含义是：让它“总结《傲慢与偏见》第一章”，对名著也许还过得去；把这一章贴进上下文，会可靠得多。1:39:23 ↗

机制幻觉常常不是“坏了的记忆芯片”，而是在模仿“自信作答”的文体。工具并不改写权重，它只是把新证据放进工作记忆。
例子Orson Kovats 这个不存在的名字，把“风格模仿 vs 事实知道”拆得很清楚。1:23:31 ↗
误区不要以为模型说“我不知道”就证明它有内省。那通常是后训练里被明确教会、或被工具流程接住的行为。也不要把一次成功的网页引用，理解成参数里已经存了这份网页。
10

自我认知是外挂上去的

讲座原意“你是什么模型、谁造了你”这类问题，在他看来有点不像话：这个东西不是人，没有持续存在，它为每次对话启动、处理 token、再关闭，上下文用完就删。没有持久自我。若不去专门编程，它会给出统计上最常见的自我介绍。较老的 Falcon 会自称由 OpenAI 基于 GPT-3 打造——这更可能是因为互联网上充满 ChatGPT 的自述，而不是它真的用了 OpenAI 的内部数据。1:41:47 ↗

开发者可以覆盖这一点。他举 Allen AI 的 OLMo：在约 100 万段微调对话里，有 240 段是写死的自我介绍（“我是 OLMo，由 AI2 开发……”）。用这些对话微调后，模型就会复述它们；若不提供，它大概又会自称某种 ChatGPT。另一种办法是隐藏的系统消息：在人类可见的对话开始前，把“你是某某、知识截止于某日”作为 token 放进上下文。你看到空白页，这些 token 其实已经在工作记忆里。两种办法都是外挂的，并不是人那种深层的自我。1:44:39 ↗

机制身份要么来自微调里的示范，要么来自上下文里看不见的系统消息。它不是模型“记得自己是谁”。
例子OLMo 的 240 段写死对话，把“自我”还原成了训练数据里的问答对。1:44:57 ↗
误区不要把模型的自我介绍当成家谱证据，也不要因为系统消息能改口，就以为它有了连续人格。
11

模型需要 token 来思考

讲座原意这一段讨论模型在解题时的“原生计算能力”。设想要为微调集写一道简单应用题：Emily 买 3 个苹果和 2 个橙子，橙子每个 2 美元，总共 13 美元，苹果多少钱？左右两个答案都写“3 美元”，但其中一个会把模型教坏。1:46:56 ↗

关键在于：模型严格从左到右、一次一个 token 地工作。每生成一个新 token，上下文都要过一遍网络。这个网络的层数是有限的——他指着演示里大约 3 层的小模型，并说现代网络更像“比如说 100 层左右”。因此每个 token 只能做大致固定、而且并不很大的计算（上下文变长会稍贵一点，但直觉上仍应看成每步预算有限）。不能指望它在一次前向里完成任意复杂的跳跃。1:49:20 ↗

如果标签是“答案是 3 美元”然后才解释，模型必须在写出“3”的那一步把全部算术塞进去；后面的文字只是事后说明，因为答案已经进入上下文。更好的标签是把中间量写出来：橙子共 4 美元，13 减 4 得 9，再得到每个苹果 3 美元。每一步都很容易，先前结果成了工作记忆。他提醒：ChatGPT 慢慢展开式子，“这些不是写给你看的，是写给模型自己的”。若不允许中间步骤，简单数字或许还能蒙对；他把数字改成 23 个苹果和 177 个橙子后，一次性作答就错了，而允许逐步计算后又做对了。1:51:07 ↗ 1:53:39 ↗

即便逐步计算，他也不完全信任“心算”。更稳妥的是让模型调用代码工具，把算术交给 Python 解释器，人还可以检查这段代码。1:55:58 ↗

机制就本节的逐步作答示例而言，中间计算是被摊到随后生成的 token上的。这些中间推理 token 不一定会展示给用户；模型写出来的解释，也不等于它内部完整的计算过程。把步骤铺开，首先是在分配生成阶段的计算，而不仅仅是文风。
例子同一道题，禁止中间步骤后在大数字上失败，允许展开后成功。这是现场演示，不是我们另行实测。1:54:25 ↗
误区不要把“请逐步思考”只当成提示技巧；也不要因为看到一长串推理文字，就自动相信每一步算术都对。需要可靠计算时，把它交给工具。
12

拼写、9.11，以及瑞士奶酪式的智力

讲座原意模型还有许多认知缺口，是这种技术的锋利边缘。它们不看字符，只看 token，所以对拼写、取字母一类任务天生吃力。人看见 ubiquitous，可以轻松指出第几个字母；模型可能把它看成三个 token，内部并没有一张清晰的字母表。著名的“strawberry 里有几个 r”曾经反复让模型出丑；到他录制时，模型已经常常能答对三个 r，但这类任务仍不该被默认期望成功。2:01:12 ↗

计数也是同一类问题：数清一长串点或字母，需要的计算量可能超出单个（或过少的）token 预算。然后是更奇怪的例子：模型有时会判断 9.11 比 9.9 大，并给出一套说辞，稍后又可能改口。他称这件事有点让人挠头，并转述：有团队深入研究过，但他本人没有读那篇论文；该团队告诉他，检查激活时，通常与圣经章节标记相关的神经元会被点亮，模型仿佛把 9.11 看成了章节号，在那种排序里 9.11 会排在 9.9 后面。这是讲者对团队说法的转述，不是定论；他也说这件事仍不完全说得通、尚未被完全理解。2:05:32 ↗ 2:06:18 ↗

他用“参差的智力 / 瑞士奶酪”来收束：模型可以在化学、生物这类问题上超过他，却在这类简单比较上突然摔倒。空洞不是整齐地分布在“低难度”一侧，而会随机出现。2:04:54 ↗

机制切分把字符焊死在块里；有限的逐步计算不适合精确计数；个别比较还会被训练里的其它模式带走。
例子strawberry 的 r、9.11 对 9.9，是他用来说明“整体很强、局部突然很笨”的公开案例。2:03:45 ↗ 2:05:32 ↗
误区不要用一道小学题失败，就全面否定模型；也不要用一道专业题成功，就推断它在所有简单题上可靠。
13

强化学习、DeepSeek-R1，以及 AlphaGo 的第 37 手

讲座原意要把最后这段组织起来，他用了上学的类比。教科书里有正文（对应预训练：先广泛接触材料），有例题和详细解法（对应监督微调：专家把步骤写给你看），还有只给最终答案的练习（对应强化学习：你自己做，再对照对错）。监督微调的缺点是：人写的“理想解法”未必是模型容易走的路，因为模型的认知不是人的认知。所以要让模型自己尝试许多条 token 序列，留下对它真正有用的。2:11:15 ↗

在可验证领域——数学、代码，对错可以自动判定——做法是：对同一道题采样许多条解答，做对的轨迹被加强，做错的被减弱。模型于是会发现对自己有效的推理过程，而不只是背诵某位标注员的写法。2:14:42 ↗

DeepSeek-R1 是他录制前不久公开的例子：这是开放权重模型，任何人可以下载（完整精度未必能在消费级机器上跑）。随着这种训练，模型不仅准确率上升，回答也变长，并出现自发的回看、重算、换一种思路。讲座引用了“等等，这是 aha moment”一类痕迹。他把这称作模型在发现“认知策略”：如何从不同角度操纵问题。没有人把这些行为写成示范，它们是被“答对就奖励”逼出来的。思考模型会先花时间推理，再给答案；他以 OpenAI 的 o1 / o3 系列为例，并说当时的 GPT-4o 等并不是思考模型。需要更强推理时，他会选思考模型，也接受更长的等待。2:27:47 ↗ 2:31:17 ↗ 2:37:17 ↗

他特别说：当时 Gemini 已提供思考模型，Anthropic 当时还没有。2:41:39 ↗

2026 补充“Anthropic 目前不提供思考模型”是 2025 年 2 月的现场判断。此后 Claude 等产品已出现扩展思考一类能力。不要把这句话当成 2026 年的产品事实。Understanding Machine 的导读也提醒：框架仍成立，若干产品细节已经过时。

强化学习能超越“模仿人类”的上限，并不是新发现。他回到 AlphaGo：先模仿人类棋谱，再靠自我对弈突破，包括对李世石（转录里一度误成 Lisa Dole）的第 37 手——事后看很高明、当时却不像人类会下的棋。开域问题上，类似的“人类从未想过的类比”在原则上是可能的，但当时仍很早期，主要在可验证领域发光。2:42:08 ↗ 2:45:29 ↗

机制有标准答案时，奖励可以直接打在结果上，过程可以由模型自己长出来。这与“抄专家的解题步骤”不是同一件事。
例子R1 轨迹里的停顿和重算，以及 AlphaGo 第 37 手，是他用来说明“发现策略、而不只是复述”的两条证据。2:31:20 ↗ 2:45:29 ↗
误区不要把思考模型多出来的等待，理解成它在权重里临时学习；那主要是在生成更多中间 token，也就是用推理时计算换准确率。也不要把原则上可能出现的“第 37 手”，说成已经在开放领域里被稳定观察到。
14

RLHF：没有标准答案时的技巧，以及它的陷阱

讲座原意到此为止，强化都发生在可验证领域。创意写作、总结、讲笑话没有标准答案。他以“写一个关于鹈鹕的笑话”为例：模型可以生成很多笑话，但无法自动判定哪个更好。若每次都请人打分，又太贵，不可扩展。2:48:28 ↗

于是有强化学习从人类反馈（RLHF，OpenAI 当时的论文，部分作者后来参与创办 Anthropic）。做法是：对人来说，给若干回答排序比直接打精确分数更容易，也比自己写一个更好的回答更便宜。用这些排序训练另一个网络——奖励模型——去模仿人类打分；再让主模型对这个奖励模型做优化。2:51:24 ↗ 2:52:37 ↗

经验上，这能改善模型，但有硬限制。优化前几百步，鹈鹕笑话或许会好一点；再继续，表现会从悬崖上掉下去——因为奖励模型只是对人类判断的有损模拟，可以被钻空子。不能像 AlphaGo 那样无限自我对弈直到超越顶尖棋手。他的判断是：RLHF “不太算真正的强化学习”，更接近一次小小的微调。3:02:29 ↗ 3:06:13 ↗ 这是他就代理奖励可被钻空子给出的个人评价，不是一条技术分类定义：前面他已经说明，有了人类偏好的模拟器之后，仍然是在对这个模拟器做强化学习；差别在于奖励来自何处、以及还能安全优化多久。2:53:08 ↗

机制当没有标准答案时，系统优化的是“评分器喜欢什么”，不是“事实上更好”。评分器一被钻空子，主模型就会跟着走偏。
例子给五个鹈鹕笑话排序，比请人写出一个完美笑话更可行；但若对这个代理目标优化太久，得到的就不是更好的笑话。2:53:46 ↗
误区不要把“更会说话、更讨人喜欢”自动理解成更诚实或更有能力。RLHF 很擅长改表达，不保证改对事实。也不要把他“不太算真正的强化学习”理解成技术分类上“RLHF 不是强化学习”——RLHF 仍然包含强化学习，差别在奖励来源和优化风险：代理奖励可被钻空子，所以不能像有标准答案那样无限加计算。
15

接下来可能是什么，以及当时他如何跟上进展

讲座原意对未来，他先谈多模态：到那时为止，讲座几乎全在讲文本，但模型会很快在音频和图像上变得更自然——能听、能说、能看、能画。基本办法并不神秘：把音频频谱切片、把图像切成补丁，都变成 token，再和文本一起放进上下文，用同一套预测下一个符号的方法训练。已经能看到早期工作。3:09:39 ↗

第二是智能体：当时多数用法仍是把单个任务“端到模型面前”，由人负责把任务串成完整工作。模型还不能在长时间里可靠地自我纠错、把任务连成许多分钟甚至数小时的工作，但这在改善。未来会看到更多需要人监督、偶尔汇报进展的长程智能体。由于模型并非不会错，数字世界里会出现类似工厂里“人机比”的“人对智能体比”，人更多地成为监督者。他还提到模型将更 Invisible 地嵌进工具，以及代表你操作键盘鼠标的计算机使用（当时举了 Operator 这类早期例子）。3:11:17 ↗

最后是一个研究上的缺口：现在的流程是先训练、再把参数冻结后部署。部署之后，模型不再从自己做过的事情里更新参数，测试时唯一的“学习”是上下文窗口里的 in-context learning。这和人在清醒经验、尤其睡眠中更新参数的方式不同。上下文是有限而珍贵的资源；一旦要处理很长的、带视频的多模态任务，只靠把窗口加长恐怕不够，需要新想法。他把这类方向称为 test time training 一类仍待探索的研究。3:13:14 ↗

2026 补充讲座说多模态“很快会变得非常原生”，并强调当时还只是开始。到 2026 年，许多消费级产品已经能语音和看图。这验证了他的方向判断，但不应当成他在 2025 年 2 月已经描述了今天某款具体产品。智能体和计算机使用同样仍在快速变化，本篇不把后来的产品细节回填进旧口播。

如何跟上？他长期使用三个来源：第一，LLM Arena 这类按人类盲评排列的排行榜，当时能看到开源权重模型（如 DeepSeek）冲到很前的位置；但他也说，近几个月这份榜被“玩”得更厉害了，不如以前信任，例如他认为很多人爱用的 Anthropic Sonnet 排在第 14，而使用更少的 Gemini 却很高，所以只能当第一遍筛选，还得在自己的任务上试。第二，Swix and Friends 的 AI News 通讯，几乎隔天更新，上部摘要有人看管。第三，X / Twitter，跟随自己信任的人。3:15:15 ↗

去哪里用模型？最强的闭源模型走官方应用或 API。开放权重模型可以用 together.ai 等托管，他个人喜欢在 Hyperbolic 上直接对话 Llama 3.1 基座模型。本地则可以用量化、蒸馏后的较小精度，在笔记本电脑上跑“还行”的模型；他常用 LM Studio，尽管嫌界面难看、型号过多。3:18:35 ↗

机制文本、声音和图像可以被统一成 token 流；但参数一旦冻结，长期记忆不会在使用中继续改写，除非研究出新的测试时训练。
例子频谱切片和图像补丁，是他用来说明“多模态不必另起一套魔法”的具体路线。3:10:25 ↗
误区不要把 2025 年 2 月排行榜上的名次，当成今天的模型实力图。连他自己当时就已经提醒：榜在被游戏化。
16

把聊天框再拆开：总图与用法

讲座原意收尾时他回到起点：在 chatgpt.com 里输入一句话并按下回车，究竟发生了什么？先是预训练得到基座模型，一种对互联网文档的有损模拟；再经监督微调，装上助手人格，成为对标注员的有损模拟；再视任务加上可验证领域的强化学习，或 RLHF 这种“小微调”。生成时，每个 token 仍然只分配到有限计算，所以需要把思考摊开，也仍然会幻觉、会在瑞士奶酪的空洞里突然数不清字母，或说不出 9.11 小于 9.9。3:21:49 ↗ 3:26:10 ↗

思考模型让人兴奋，因为原则上它可能在开放领域里出现类似第 37 手的新思路，但当时仍是雏形，主要在数学和代码等可验证处发力。他个人每天使用这些模型几十到上百次，认为它们会创造巨大财富，也坚持列出缺点：即便是强化学习过后的模型，仍会胡编、算错、数错。3:29:37 ↗

把它们当成工具箱里的工具，不要完全信任。用它们找启发、写初稿、提问，但始终检查、核验，并对自己的工作产物负责。这样你才会在工作里非常成功。3:30:32 ↗
容易混在一起的两件事实际差别依据
参数里的知识 / 上下文里的知识前者是模糊的长期回忆，后者是当下的工作记忆。重要材料应贴进上下文。1:39:23 ↗
训练 / 推理训练改参数；使用产品时通常只在推理，参数冻结，只采样。0:30:29 ↗
流畅的文本 / 正确的事实模型首先在模仿答案的形状和自信的腔。流畅不保证它知道，更不保证它查过。1:22:44 ↗
给用户看的步骤 / 给模型用的步骤中间 token 首先是模型自己的计算纸，不是排版装饰。1:53:39 ↗

17

写程序时怎么用这些认识

讲座原意上面多数含义其实已经是给使用者的：把原文放进上下文；让模型把步骤写出来；算术交给代码；把输出当初稿而不是定论；在自己的任务上试模型，而不是只看排行榜。

延伸假设下面这一小节不是讲座内容，只是把同一组机制，放到手机终端和实时通信场景里看一眼，供你工作时对照，并不构成实测结论。

若你在做实时语音或 WebRTC 通话中的助手：讲座里“模型需要 token 来思考”和低延迟轮次之间会直接打架。若产品强迫模型立刻、短促地开口，并且不允许它在开口前拥有独立的内部思考预算，才更接近要求它在一次或极少几次前向里跳完难题，失败模式会更接近他演示的“禁止中间步骤”。不能把“先发出的声音”和“思考”绝对等同。更稳妥的产品形状，可能是把“必须马上接话”和“可以在后台展开计算或调用工具”分成两条时间线，而不是指望同一句回复既低延迟又高可靠。

通话状态、编解码约束、刚刚说过的话、检索到的设备文档，应当被明确放进上下文，当作工作记忆来管理，而不是假设参数“还记得产品手册”。需要事实时走工具，再把结果贴回来；不要把未核验的模型陈述直接接到实时媒体路径上。最后，每 token 的固定计算量和网络 RTT 是两笔不同的延迟预算，不能互相替代，却会叠在同一条用户可感知的等待里。
