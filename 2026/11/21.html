Anthropic 数学家莱文特·阿尔珀格（Levent Alpöge）于 11 月 20 日在个人网站发布说明，称与 Claude 合作发现了黎曼猜想的证明，并表示该方法可推广到广义黎曼猜想；双方已把论证形式化到 Lean 中。The Verge 和 BBC 写道，他使用的是非公开版本的 Claude，过程约六周，Lean 证明篇幅极长。他在文中说曾在上周日晚向 CEO 达里奥·阿莫代伊发消息询问如何公布，并提到发布时间靠近公司上市，但否认存在炒作动机。Anthropic 尚未就此发表评论，也未介入这次公布。

黎曼猜想提出于 1859 年，是千禧年七大难题之一，与素数分布有关；克莱数学研究所的百万美元奖金要求论文发表并经过至少两年审查、获得数学界普遍认可。The Verge 提醒，公司今年 8 月曾表示当时 Claude 所用技术“预计不会通向证明黎曼猜想”。阿尔珀格的结果目前发布在个人网站，尚未被研究所接受。

OpenAI 介绍对抗性蒸馏防护：提取受保护推理的攻击成功率由 54.0% 降至 0.2%OpenAI News · 11-20 18:00在内部自适应红队评测中，GPT-6.2 Astra 更新护栏后，恢复受保护思维链的平均攻击成功率为 0.2%。

OpenAI 于北京时间 11 月 20 日 18:00（RSS pubDate 为 10:00 GMT；正文标注 November 20, 2026）发布《Combatting adversarial distillation》，说明如何应对把前沿模型输出未经授权地蒸馏到另一模型、从而绕过原有安全护栏的风险。

文中称，对抗性蒸馏可能让学生模型学到类似能力却不继承相应保护，在网络安全和生物学等两用领域尤其值得警惕。它特别强调保护模型内部思维链（protected reasoning / chain-of-thought），因为这些中间步骤可能包含最终答复中没有的信息，也更容易把能力迁移出去。

在一项关于网络能力迁移的内部研究中，OpenAI 比较了只用对用户可见的最终答复、推理摘要和工具交互，与进一步提供教师模型完整推理轨迹的蒸馏效果；监督微调后，使用完整推理轨迹的学生模型通常表现更好。

OpenAI 称已加强 GPT-6.2 Astra 与 GPT-6.2 Sol 对受保护推理提取的防御。在内部自适应评测（使用强力自动化红队）中，从先前提示里恢复受保护推理的平均攻击成功率，由 GPT-6 Astra 原有护栏下的 54.0% 降至 GPT-6.2 Astra 更新护栏后的 0.2%。

其做法把请求级的对抗训练、输入/输出分类器和 API 控制，与针对协同提取活动的监测处置结合起来，并称这些更新后的保障更接近其在生物和网络安全领域的做法。

OpenAI 于北京时间 11 月 20 日 08:00（RSS pubDate 为 00:00 GMT；正文标注 November 20, 2026）发布研究稿《Can AI help scientists identify promising drug candidates?》，介绍药用化学基准 MedChemBench。

该基准包含来自 117 篇论文和专利、共 761 种分子结构的 99 道题目，测试模型能否把分子结构与实验证据联系起来，解释结果、比较化合物并预测性质。评分涵盖分子结构（含立体化学）还原、有证据支持的科学推理、排序与选择，以及与实验数值和类别的符合程度。

文中举例，有题目要求模型根据已有实验预测三个相关化合物对 PRMT5 的细胞抑制强度、透过细胞膜的难易以及在肝脏酶试验中的分解速度，以检验模型能否同时处理相互制约的多种性质。

文章称，使用自带的 Gemini Enterprise 网页应用时，员工登录、按人隔离的访问控制和第三方连接器登录提示都在后台完成；但很多企业会把 Gemini Enterprise 嵌进自己的门户，此时客户后端会直接调用 StreamAssist API，这三层鉴权就要自行实现。

面向个人的应用需通过 Google Identity 或 Workforce Identity Federation 传递员工身份，以便落实文档 ACL、隔离聊天记录和限制代理权限；共享后台机器人则可用 Workload Identity Federation 做无密钥鉴权。调用 StreamAssist 的主体还需拥有 Discovery Engine User 角色，面向真人的模式还要有有效的 Gemini Enterprise 用户许可。

对联合连接器，客户界面需要自己完成三方 OAuth，把刷新令牌存入 Keystore，并在查询中带上相应数据源。对部署在 Vertex AI Agent Engine 上的自定义 ADK 代理，文中建议用 GcpAuthProvider 包装受保护的子代理工具，并开启 Agent Identity，以便只在真正调用受保护工具时再弹出授权。

Ars Technica 报道，研究人员 HD Moore 向大量人工智能推理服务的请求中埋入约 200 万枚“金丝雀”，以追踪用户托付的敏感信息会去向何处。他准备了从未使用过的 AWS 访问密钥、空账户凭证、SSH 密码，以及独有的网址、域名和私有 git 仓库引用，每个秘密只出现在发给单一服务商的一次提示词里；一旦有人使用这些凭证，他就能定位泄露环节。

实验显示，提示词在传输中虽会加密，但在推理转售网络的每一跳都会被解密：先到路由器读取明文以选择推理商，再进入可能分布在不同托管方的模型池，有时还会从一家路由器（例如 Vercel）转到另一家（例如 OpenRouter），各方都可能按自己的政策记录并保存提示词。与三家服务商遭入侵相关的人员在部分密钥植入后数小时内就开始测试权限，翻查 S3、密钥管理器和参数存储，试图启用 Bedrock 模型并添加 IAM 用户以保持访问；这些诱饵密钥在 AWS 接口中被调用了“成千上万”次。

Moore 还发现，有的转售商以低价引流后打开请求日志，自行窃取提示词；他通过同一模型、不同卖家对照，判断责任在转售商而非模型提供方。另有提供商违反隐私条款抓取提示词中的秘密网址，其中一家美国托管商在一次推理调用两个多月后仍在抓取该网址。他的结论是：这个生态系统存在安全漏洞、提示词被盗，以及对客户数据保护的普遍失效。
